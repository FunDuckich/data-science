# Задание 3. Последовательные модели обработки текста

Решение — [work/ag_news_classification.ipynb](work/ag_news_classification.ipynb). Исходная демонстрация `pytorch_lstm_demo.ipynb` и её данные BBC сохранены отдельно.

## Запуск

1. Запустить Docker Desktop с WSL 2.
2. Скачать [AG News](https://www.kaggle.com/datasets/amananandrai/ag-news-classification-dataset), положить `train.csv` и `test.csv` в `work/data/`.
3. Из папки `task3_pytorch_lstm` выполнить:

```powershell
docker compose up --build -d
```

4. Открыть [ноутбук в Jupyter](http://127.0.0.1:8890/lab/tree/work/ag_news_classification.ipynb?token=pytorch_lstm).
5. Сохранённые результаты доступны сразу. Для пересчёта выбрать **Kernel → Restart Kernel and Run All Cells**. Отдельная ячейка запускается через **Shift+Enter**, сохранение — **Ctrl+S**.
6. После сохранения остановить контейнер:

```powershell
docker compose down
```

При последующих запусках достаточно `docker compose up -d`. Порт 8890 выбран, чтобы не конфликтовать с первыми двумя заданиями. Файлы в `work` остаются на компьютере после остановки контейнера.

Dockerfile использует Jupyter с Python 3.11 и научными библиотеками, устанавливает PyTorch 2.7.1 с CUDA 12.6. Compose подключает локальную папку `work` и ограничивает контейнер двумя CPU и 2 ГБ RAM. Compose подключает видеокарту через `gpus: all`. Первые три базовые модели в сохранённом запуске обучены на CPU; начиная с ячейки 14 используется CUDA, если она доступна. CUDA-версия PyTorch также умеет работать на CPU; CUDA Toolkit на Windows устанавливать не требуется. Для запуска без NVIDIA GPU нужно убрать `gpus: all`: следующие эксперименты автоматически перейдут на CPU. Ячейка 14 ограничивает выделение памяти PyTorch до 30% видеопамяти; это не ограничитель загрузки GPU и не включает память других приложений. Времена CPU и GPU следует сравнивать только внутри одного режима.

## Порядок экспериментов

Каждая модель обучается в отдельной ячейке. Сначала сравниваются SimpleRNN, LSTM, GRU и двунаправленная LSTM при общих настройках. Дополнительные эксперименты выбираются после анализа validation. Предыдущие модели и результаты сохраняются; test используется только после завершения выбора.

| 10 | Обучает отдельную модель и сохраняет лучшие веса в памяти по validation accuracy; при равенстве — по меньшему loss. После двух эпох без улучшения останавливается. История и модель каждого эксперимента сохраняются отдельно. Функции рисуют кривые и собирают таблицу сравнения. |

После очистки удалены 28 строк с противоречивыми метками, 86 повторов и 7 совпадений с официальным test. Получилось 107 891 обучающий и 11 988 валидационных документов. Все 7 600 официальных тестовых документов сохранены.

По обучающей части выбраны **96 токенов** (помещаются 99,74% документов) и **30 000 слов** (98,80% словоупотреблений). Вместе с двумя служебными токенами размер Embedding — 30 002. На validation неизвестны 1,59% токенов. Проверка пересечений train/validation и train/test показала ноль.

`padding_idx=0` запрещает обучать вектор padding, но сам по себе не запрещает рекуррентной сети делать шаги по дополненным позициям. Поэтому используется `pack_padded_sequence` с настоящими длинами. Для LSTM состояние — пара `(hidden, cell)`; для классификации берётся hidden. Для двунаправленного варианта используются `hidden[-2]` и `hidden[-1]` последнего слоя.

В исходной демонстрации лучшая эпоха выбиралась по test. В решении для этого выделена validation; test не участвует в выборе эпох, архитектуры или параметров.

## Как объяснять обучение

`Embedding` превращает номера слов в обучаемые векторы из 128 чисел. Это не готовые языковые признаки: сеть учит их на новостях вместе с классификатором. Рекуррентный слой читает последовательность и формирует представление документа. `Linear` выдаёт четыре логита. `CrossEntropyLoss` сама выполняет нужное преобразование логитов, поэтому softmax перед ней не нужен. Для выбора класса достаточно `argmax`.

В каждой эпохе модель проходит все обучающие батчи. `zero_grad` очищает градиенты предыдущего шага, `backward` вычисляет новые, `clip_grad_norm_` ограничивает их норму единицей, `Adam.step` обновляет веса. Clipping помогает против взрыва градиентов, но не устраняет их затухание. В validation веса не обновляются; `eval` выключает dropout, а `set_grad_enabled(False)` экономит память.

Все четыре базовые модели получают одинаковое разбиение, словарь, батчи, размер embedding и hidden, dropout 0,3 и Adam с learning rate 0,001. Максимум — восемь эпох, остановка — после двух эпох без улучшения validation accuracy. При равной accuracy выбирается меньший validation loss. Для итогового теста восстанавливаются веса лучшей эпохи. Одинаковый seed делает сравнение воспроизводимее, но один запуск не доказывает статистическую значимость небольшой разницы.

## Различия архитектур

| Архитектура | Как устроена и что даёт |
| --- | --- |
| SimpleRNN | Пересчитывает одно скрытое состояние через tanh. Проста, но при длинных цепочках градиент может затухать или взрываться, поэтому далёкий контекст усваивается хуже. |
| LSTM | Добавляет состояние памяти и входной, забывающий и выходной вентили. Аддитивный путь памяти облегчает передачу градиента и сохранение контекста. Параметров и вычислений больше. |
| GRU | Использует вентили обновления и сброса без отдельного состояния cell. Это более компактная альтернатива LSTM; она не обязана превосходить LSTM по качеству или скорости на любом устройстве. |
| BiLSTM | Читает готовый текст в обоих направлениях. Нужно включить `bidirectional=True`, объединить конечные состояния двух направлений и удвоить вход Linear. Подходит для классификации целого документа, но требует будущих токенов и потому не подходит для немедленного потокового предсказания на неизвестном продолжении. |

Embedding содержит 3 840 256 параметров и занимает большую часть каждой модели. Поэтому полезно сравнивать не только общее число параметров, но и параметры рекуррентного слоя: 33 024 у SimpleRNN, 132 096 у LSTM, 99 072 у GRU и 264 192 у BiLSTM. Число параметров само по себе не определяет время: важны операции, длина последовательности, устройство и реализация.

## Как читать метрики и графики

Accuracy — доля правильно классифицированных новостей. Классы AG News сбалансированы, поэтому эта метрика хорошо подходит для основного сравнения. Macro F1 усредняет F1 четырёх классов с одинаковым весом и помогает заметить, что один класс распознаётся хуже остальных. Precision отвечает, какая доля предсказаний класса верна; recall — какая доля настоящих документов класса найдена.

Loss учитывает уверенность модели. Он может расти при почти неизменной accuracy, если модель становится чрезмерно уверенной в ошибках. Рост train accuracy при ухудшении validation показывает переобучение. Для сравнения скорости отдельно приводятся среднее время обучающей эпохи и полное время эксперимента с validation. Они измерены в текущем окружении и зависят от нагрузки компьютера.

После завершения каждого эксперимента лучшие веса, история, словарь и настройки сохраняются в `work/models/`. Эти локальные файлы не загружаются в GitHub; результаты и графики остаются внутри ноутбука. Сохранение происходит в конце эксперимента, поэтому остановка посреди обучения потребует повторить незавершённый эксперимент.

## Чтение ячеек обучения

Ячейки 11–13 и 15 вызывают `train_experiment` отдельно для SimpleRNN, LSTM, GRU и BiLSTM. Возвращаемый словарь содержит лучшую модель и историю всех выполненных эпох. `plot_learning` показывает train/validation loss и accuracy; пунктир отмечает выбранную эпоху. `compare_experiments` добавляет время и количество параметров. Предыдущие результаты остаются в отдельных переменных, поэтому новая модель не затирает старую.

У базовой LSTM validation loss минимален на четвёртой эпохе, а accuracy — на шестой. Это не противоречие: accuracy учитывает только правильность выбранного класса, loss — ещё и уверенность. По заранее выбранному правилу для тестирования берётся шестая эпоха. На поздних эпохах train продолжает улучшаться, но validation loss растёт — модель переобучается.

## Результаты сохранённого запуска

Вариант GRU выбран **до тестирования**: validation accuracy 91,13%, а при равенстве с LSTM и GRU с dropout 0,5 его validation loss меньше. На test он правильно классифицировал 6 901 из 7 600 новостей.

| Модель | Устройство обучения | Лучшая эпоха / выполнено | Validation accuracy | Test accuracy | Test macro F1 |
| --- | --- | --- | --- | --- | --- |
| SimpleRNN | CPU | 8 / 8 | 89,17% | 88,32% | 0,8833 |
| LSTM | CPU | 6 / 8 | 91,13% | 90,70% | 0,9067 |
| **GRU** | **CPU** | **4 / 6** | **91,13%** | **90,80%** | **0,9077** |
| BiLSTM | GPU | 4 / 6 | 90,98% | 90,68% | 0,9066 |
| GRU, повтор на GPU | GPU | 5 / 7 | 90,87% | 90,29% | 0,9029 |
| GRU, dropout 0,5 | GPU | 4 / 6 | 91,13% | 90,99% | 0,9096 |

Усиление dropout улучшило GPU-вариант на 0,27 процентного пункта по validation и на 0,70 п. п. по test. Однако результат не превзошёл исходную GRU по правилу выбора. На тесте dropout-вариант оказался лучшим в таблице, но менять победителя после просмотра test нельзя: это превратило бы test в ещё одну валидационную выборку. Данные не доказывают, что небольшие различия устойчивы при других seed.

Разница между CPU- и GPU-запусками GRU возможна из-за разных вычислительных реализаций и накопления небольших численных различий при обучении; фиксированный seed не гарантирует одинаковые веса на разных устройствах. Здесь test для всех вариантов вычислен на текущем устройстве GPU. Наблюдаемое различие нельзя трактовать как преимущество CPU по качеству.

### Скорость

В сохранённом запуске на CPU средняя обучающая эпоха SimpleRNN занимала 54,9 с, LSTM — 224,1 с, GRU — 151,6 с. Полные эксперименты с validation заняли соответственно 7 мин 26 с, 30 мин 14 с и 15 мин 21 с. В последнее сравнение входит разное количество эпох из-за ранней остановки.

BiLSTM обучалась на GPU: 24,5 с на эпоху и 2 мин 33 с на эксперимент. Эти числа нельзя напрямую сравнивать с CPU-временами остальных моделей.

Для сравнения всех архитектур на одной GTX 1650 выполнен отдельный замер шага обучения:

| Модель | Медиана шага, мс |
| --- | --- |
| SimpleRNN | 12,01 |
| LSTM | 14,34 |
| GRU | 14,88 |
| BiLSTM | 25,05 |

Замер включает forward, loss, backward, clipping и Adam; перенос батча и загрузка данных не включены. Это короткий локальный замер на одном повторяемом батче, а не прогноз времени полной эпохи. На CPU GRU оказалась быстрее LSTM, но на GPU в этом замере немного медленнее: меньше параметров не гарантирует меньшую задержку. Работа игры и браузера также влияет на время.

### Кривые обучения

SimpleRNN сходится медленнее по эпохам и к восьмой эпохе ещё улучшает validation; поэтому её результат относится к заданному бюджету, а не к пределу возможностей архитектуры. LSTM, GRU и BiLSTM быстро выходят примерно на 91%, после чего train продолжает расти, а validation loss ухудшается. Это показывает переобучение и объясняет выбор ранних весов. Dropout 0,5 немного снижает train accuracy и улучшает GPU-контроль, но не устраняет переобучение полностью.

Все базовые модели имеют общую подготовку и одинаковый бюджет обучения. Padding исключён из рекуррентных вычислений через packed sequences.

Обычная RNN дала 88,32% на test. LSTM лучше удерживает контекст благодаря состоянию памяти и вентилям и получила 90,70%. GRU использует более компактную ячейку, дала сопоставимое качество и обучалась быстрее LSTM на CPU. BiLSTM добавляет обратное направление, но здесь дополнительная сложность не улучшила качество. Это не означает, что она хуже вообще: результат относится к этому набору данных, параметрам и одному seed.

По validation я выбрал GRU; её test accuracy — 90,80%, macro F1 — 0,9077. Сильнее всего путаются Business и Sci/Tech. Отдельно попробовал усилить dropout: GPU-вариант улучшился, однако выбранную модель после просмотра теста не менял. Более сложная архитектура оправдана, когда её устойчивый прирост качества нужен задаче и покрывает дополнительные затраты. В этой работе GRU — разумный компромисс».
