## Как запустить

Нужны Docker Desktop с работающим Linux/WSL 2 и Python 3.11+ на Windows для скачивания данных. Все зависимости Spark, pandas, matplotlib и Jupyter находятся в фиксированном Docker-образе. Для полного запуска желательно 16 ГБ оперативной памяти на компьютере и не менее 8 ГБ, доступных Docker. Порт 8888 должен быть свободен: сначала остановите контейнер первого задания.

```powershell
git clone git@github.com:FunDuckich/data-science.git
cd data-science\task2_pyspark_als
python download_data.py
docker compose up -d --wait --wait-timeout 360
```

Откройте <http://127.0.0.1:8888/?token=pyspark_ml>, затем `work/book_recommendations.ipynb`. Для полного повторения выберите **Kernel → Restart Kernel and Run All Cells**. После работы:

```powershell
docker compose down
```

Автоматически выполнить весь ноутбук, сохранить выводы, экспортировать HTML и остановить контейнер можно одной командой:

```powershell
.\run.ps1 -Profile full
```

Короткая проверка на 400 наиболее активных пользователях, одной конфигурации ALS и 20 пользователях для ranking-метрик:

```powershell
.\run.ps1 -Profile smoke
```

`smoke` пишет в `work/artifacts/smoke/` и не заменяет основной ноутбук. `full` использует все исходные записи и заменяет основной ноутбук выполненной версией. `run.ps1` останавливает контейнер в `finally`, в том числе при ошибке. При сбое остаются `failed.ipynb` и `execution_progress.json`; успех подтверждается `completion.json`. Если политика Windows запрещает локальный скрипт, можно выполнить его в отдельном процессе: `powershell -ExecutionPolicy Bypass -File .\run.ps1 -Profile full`.

Исходные Books.csv, Ratings.csv и Users.csv не включены в Git. Скрипт скачивает официальный архив Kaggle и записывает размеры и SHA-256 в `work/data/source.json`. Если Kaggle требует авторизации или недоступен, скачайте архив со [страницы датасета](https://www.kaggle.com/datasets/arashnic/book-recommendation-dataset) вручную и положите `Books.csv`, `Ratings.csv`, `Users.csv` в `work/data/`, затем повторите запуск. ## Как получить рекомендации для другого пользователя

Поднимите контейнер и создайте новый Python-ноутбук в `work`. Выполните:

```python
from recommender import recommend_books

recommend_books(user_id=12345, k=3)
recommend_books(user_id=2147483647, k=3)
recommend_books(user_id=2147483647, k=3, liked_isbns=['0195153448'])
```

Первый вызов лениво загружает сохранённую модель и таблицы. Если пользователь имеет фактор ALS, используется ALS; иначе — популярность. Третий вызов помогает новому пользователю через автора и издателя выбранных книг. Наличие ID в `Users.csv` само по себе не делает пользователя тёплым. Нужен фактор, построенный по явной обучающей оценке. ISBN передаются строками. Неизвестные ISBN выводятся сообщением и пропускаются. `k` допустим от 1 до 100; если доступных непрочитанных книг меньше, возвращается более короткий список.

В результате есть `rank`, `isbn`, `title`, `author`, `source`, `score`, `reason`. Значения `score` разных источников несопоставимы: для ALS это предсказанная оценка, для контента — совпадения метаданных, для популярности — число читателей. История обучения и ISBN из `liked_isbns` исключаются. Рекомендатель не записывает новые взаимодействия и не дообучается от вызова функции: для обновления факторов нужен новый цикл обучения. Тёплому пользователю переданные ISBN исключают уже знакомые книги, но не меняют его обученный вектор.

1000 пользователей в сохранённой демонстрационной выгрузке — размер примера и оценочной когорты, а не ограничение API. Можно запрашивать любой int32 ID. Факторы доступны только пользователям и книгам, встречавшимся в явной train-выборке.

## Как устроен эксперимент

| Этап | Решение | Зачем |
| --- | --- | --- |
| Загрузка | Явные схемы, ISBN как строка, CSV с кавычками и многострочными полями | Сохранить ведущие нули и правильно прочитать названия |
| Качество | Счётчики пропусков, некорректных оценок, дубликатов и отсутствующих метаданных | Сделать очистку проверяемой |
| Повтор пары | Среднее положительных оценок, нули не входят в среднее | Одна пара не попадает в разные выборки |
| Каталог | Объединение ISBN каталога и взаимодействий, устойчивый int32 ID | Не терять оценки неизвестных в Books.csv книг |
| Разбиение | Хеш пары с seed 42, 80/10/10 | Воспроизводимость и отсутствие пересечения пар |
| История | Все train-взаимодействия, включая нули | Не рекомендовать уже известные пользователю книги |
| Популярность | Уникальные читатели train, затем сглаженная оценка и ISBN | Простая воспроизводимая база сравнения |
| Соседи | Общих книг ≥5, сходство с поправкой на размер пересечения | Не объявлять соседом человека по одному случайному совпадению |
| ALS | Явные оценки 1–10, неотрицательные факторы | Восстановление шкалы оценок |
| Подбор | 3 rank × 3 regParam, 15 итераций, validation RMSE | Test не влияет на выбор |
| Test | RMSE, MAE, покрытие; отдельно clipped RMSE | Не скрывать ошибки и холодные пары |
| Ранжирование | Recall@10, NDCG@10, покрытие каталога | Оценить попадания и порядок в выдаче |
| Гибрид | ALS → контент для нового с предпочтениями → популярность | Получать выдачу при отсутствии факторов |
| Сохранение | ALS + каталог/ID + история + популярность | Восстановить весь рекомендательный сервис, а не только матрицы |

Каталог целиком можно использовать как известные метаданные. Популярность, среднее, соседство и факторы считаются только на train. В датасете нет временных меток; хеш-разбиение не доказывает качество на будущих взаимодействиях. Validation-пары не добавляются в обучение после выбора — тест оценивает ту же выбранную модель.

## Ответы на вопросы преподавателя

**Почему ноль не плохая оценка?** В описании Book-Crossing это неявное взаимодействие. Если обучать явный ALS на нулях, мы подменим отсутствие явного мнения отрицательным предпочтением.

**Почему ISBN нельзя сразу привести к числу?** Есть ведущие нули и буквенные символы. ALS нужны int32 ID, поэтому сохраняется отдельное отображение.

**Что делает ALS?** Ищет короткие векторы пользователей и книг, скалярное произведение которых приближает наблюдаемую оценку. Чередует решение задачи для одной группы векторов при фиксированной другой. Регуляризация уменьшает переобучение; в Spark ALS-WR её вес масштабируется числом наблюдений соответствующего пользователя/товара.

**Чем rank отличается от числа рекомендаций?** Rank — размер скрытого вектора. Число рекомендаций задаётся независимо параметром `k`.

**Что такое холодный пользователь?** Пользователь без обученного фактора. Его ID может присутствовать в Users.csv, но этого недостаточно. При неизвестном ID ALS возвращает NaN.

**Хватает ли одной оценки?** Одной явной train-оценки достаточно, чтобы построить фактор и технически получить предсказания по известным модели книгам. Этого мало для надёжной оценки вкуса. Оценка, полученная уже после обучения, автоматически в фактор не попадёт. Единственный ноль в нашем протоколе фактор не создаёт.

**Почему не просто `coldStartStrategy='drop'`?** Так пропадут неудобные строки, а покрытие станет незаметным. Здесь NaN сохранены, доля холодных пар показана отдельно; drop продемонстрирован без нового обучения.

**Почему `RMSE` недостаточно?** Он не измеряет порядок топа, разнообразие, новизну, вероятность клика и успешность покупки. Особенно опасно сравнивать RMSE на разных подмножествах после удаления NaN.

**Что показывают Recall и NDCG?** Recall@10 — долю релевантных test-книг, найденных в первых десяти позициях. NDCG учитывает, насколько высоко стоят попадания, и нормирует результат на идеальный порядок. Релевантность здесь — явная оценка ≥8.

**На ком рассчитаны ranking-метрики?** На детерминированной когорте до 1000 пользователей с фактором и релевантной тестовой книгой с фактором. Для ALS и популярности одинаковые кандидаты, исключения и truth. Это оценка тёплого сценария, не всех пользователей.

**Почему у ALS могут быть плохие топы при нормальном RMSE?** Ошибка рейтинга и качество ранжирования — разные цели. Для редких книг оценки нестабильны; отсутствующие взаимодействия не входят как отрицательные примеры. Полезны настройка по NDCG, implicit ALS, ограничение ненадёжных кандидатов и отдельный ранжировщик — но эффект надо измерять.

**Почему нет встроенного классического user-kNN?** В Spark ML API есть ALS. Реализованный точный self-join на общих книгах может порождать очень много пар и сетевых обменов. Это проблема масштаба и обновления; не доказательство, что соседство невозможно. Для промышленного поиска используют сокращение кандидатов и приближённые методы.

**Как сравниваются соседи?** Сначала минимум пять общих явно оценённых книг. Затем `n/(n+10) × (1−MAE/9)`: больше совпадений и меньше расхождений дают более высокий результат. Книги соседей с оценкой ≥8 объединяются; уже известные целевому пользователю исключаются.

**Как помочь холодной книге?** ALS без фактора не умеет её оценивать. Контентный путь может показать её по автору/издателю. Для реального сервиса нужны описания, жанры, эмбеддинги и контролируемое исследование новых книг. Здесь жанры не выдумываются — их нет в файлах.

**Где распределённость?** Преобразования DataFrame, shuffle и ALS исполняет Spark. Текущий стенд — локальный режим в одном контейнере. Код демонстрирует распределяемые операции, но аппаратное масштабирование несколькими машинами в этом эксперименте не проверялось.

**Зачем сохранять дополнительные таблицы?** Одни факторы не дадут названия, не исключат прочитанное и не помогут холодному пользователю. Нужны отображение ID, каталог, история и популярность.

**Почему маленькие таблицы переводятся в pandas?** Только для отображения, графиков и ограниченной выгрузки. Join, агрегирование, разбиение, обучение и отбор кандидатов выполняются Spark. Весь датасет не переводится в pandas для обучения.

## Построчный разбор кода для защиты

Нумерация ниже локальная для каждой кодовой ячейки, в порядке выполнения. Строки, объединённые
скобками, образуют одно выражение: диапазон поясняет все его продолжения. Для циклов и функций
сначала приведено назначение блока, затем его отдельные инструкции. Пустые строки отделяют
логические шаги и ничего не исполняют. `.` вызывает метод объекта; цепочка методов строит план.
`F.col` обозначает колонку Spark, `F.lit` — константу в каждой строке, `alias` — имя результата.
`select` выбирает колонки, `filter` — строки; `groupBy().agg()` агрегирует; `join` соединяет;
`left_anti` оставляет строки без соответствия. `Window` задаёт порядок внутри группы,
`row_number` нумерует её строки. `cache` предлагает хранить результат, а `count`, `collect`,
`toPandas` и `write` запускают ленивые вычисления. `checkpoint(eager=True)` материализует данные
и обрывает предшествующий план. `coalesce` уменьшает число файлов при сохранении. `lambda`
задаёт короткую функцию; `withColumn` добавляет или заменяет столбец. `assert` — исполняемая проверка.
