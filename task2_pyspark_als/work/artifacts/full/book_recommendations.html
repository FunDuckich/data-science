Рекомендательные системы книг в PySpark¶

Цель: сравнить популярность, поиск соседей средствами DataFrame и ALS, затем построить гибрид с поддержкой холодного старта. Данные: Book-Crossing, опубликованные на Kaggle. Ноль означает неявное взаимодействие, оценки 1–10 — явное предпочтение. Ноутбук выполняется целиком командой ./run.ps1; профиль full использует весь датасет.

Протокол фиксируется до обучения: разбиение по паре пользователь–книга 80/10/10, выбор ALS по validation RMSE, однократная итоговая оценка на test. Временных меток здесь нет: это случайная проверка восстановления оценок, а не имитация будущего потока.

1. Чтение, качество данных и разведочный анализ¶

ISBN остаётся строкой: ведущие нули значимы. CSV читаются по заданной схеме, а не через угадывание типов. Удаляются записи без корректного пользователя, ISBN или оценки 0–10. Отсутствие названия не удаляет взаимодействие: для неизвестных ISBN создаётся строка каталога. Возраст и место проживания не используются как признаки предпочтений: они неполны и для этой работы не нужны. Некорректный год публикации превращается в null.

4. Коллаборативная фильтрация без ML: три соседа¶

Сравниваем только общие явно оценённые книги. Требуем не менее пяти совпадений. Сходство n / (n + 10) × (1 − MAE / 9) лежит в [0, 1]: первая часть штрафует малую опору, вторая учитывает близость оценок на шкале 1–10. Это выбранная эвристика, не обученная модель. Соседи упорядочиваются по сходству, числу общих книг, MAE и ID. Рекомендуются их оценки ≥8; все train-взаимодействия пользователя, в том числе нули, исключаются.

В Spark ML нет штатного user-kNN рекомендателя. Точный поиск соседей для всех пользователей создаёт большое число пар, shuffle и дорогие пересчёты при обновлении. ALS представляет предпочтения компактными факторами. Это объясняет инженерные преимущества ALS, но не означает, что поиск соседей невозможен: существуют приближённый поиск и ограничение кандидатов.

5. Обучение ALS и выбор гиперпараметров¶

Явный ALS приближает матрицу оценок произведением факторов пользователей и книг, попеременно оптимизируя их с регуляризацией. rank — размерность факторов, regParam — сила регуляризации. nonnegative=True ограничивает факторы неотрицательными значениями; оценки не обязаны лежать в 1–10. implicitPrefs=False: нули не подаются как отрицательные оценки. Девять вариантов сравниваются на одной validation-выборке; выбор по raw RMSE, затем меньшему rank и большей регуляризации. После выбора модель не переобучается на validation: определение истории и тестового протокола остаётся неизменным. nan позволяет честно посчитать покрытие, а не скрыть холодные пары.

grid = [(r, reg) for r in [10, 20, 40] for reg in [0.01, 0.1, 1.0]] if PROFILE == 'full' else [(5, 0.1)]
trials = []
best_key, best_model = None, None
for rank, regularization in grid:
    started = time.monotonic()
    estimator = ALS(userCol='user_id', itemCol='item_id', ratingCol='rating', rank=rank,
                    regParam=regularization, maxIter=15 if PROFILE == 'full' else 3, seed=SEED,
                    nonnegative=True, implicitPrefs=False, coldStartStrategy='nan',
                    numUserBlocks=6, numItemBlocks=6, checkpointInterval=2)
    model = estimator.fit(train)
    scored = model.transform(validation).cache()
    warm = scored.filter(~F.isnan('prediction') & F.col('prediction').isNotNull())
    metrics = error_metrics(warm)
    trial = {'rank': rank, 'regParam': regularization, **metrics,
             'coverage': metrics['n'] / validation.count(), 'seconds': time.monotonic() - started}
    trials.append(trial)
    key = (metrics['rmse'], rank, -regularization)
    if best_key is None or key < best_key:
        best_key, best_model = key, model
        best_model.write().overwrite().save(str((OUT / 'inference/model').resolve()))
    scored.unpersist()
    print('ALS trial', json.dumps(trial), flush=True)
save_table(pd.DataFrame(trials), 'als_search')

6. Итоговый тест: ошибки и покрытие¶

RMSE сильнее штрафует большие ошибки оценки; MAE легче интерпретировать в баллах. Обе метрики описывают восстановление явных оценок, но не порядок выдачи, разнообразие или удовлетворённость. Сравниваем ALS, общее среднее и сглаженное среднее книги на одних и тех же тёплых test-парах. Отдельно показываем долю всех пар, на которых ALS способен предсказать. Clipped RMSE приводится отдельно и не используется для выбора модели.

7. Качество ранжирования на полном каталоге факторов¶

Фиксируем до 1000 пользователей с фактором ALS и хотя бы одной релевантной test-книгой (оценка ≥8), которая также имеет фактор. Отбор детерминирован хешем ID. Это условная оценка тёплого сценария, не качество для всех пользователей. Полноту и NDCG считаем по всем доступным кандидатам модели, без сэмплирования отрицательных примеров. Неоценённые книги не считаются доказанно плохими: offline-метрики на наблюдаемых оценках имеют смещение отбора.

Из выдачи удаляется train-история. Начальные 50 кандидатов ALS расширяются вдвое, если после фильтрации их недостаточно. Для популярных книг используется тот же каталог факторов, та же история, тот же набор пользователей и релевантных книг.

def ranking_metrics(recommendations, relevant_pairs, users, catalog_size, k=10):
    hits = recommendations.join(relevant_pairs.withColumn('hit', F.lit(1.0)), ['user_id', 'item_id'], 'left').fillna({'hit': 0.0})
    observed = hits.groupBy('user_id').agg(F.sum('hit').alias('hits'), F.sum(F.col('hit') / F.log2(F.col('rank') + 1)).alias('dcg'))
    ideal = relevant_pairs.groupBy('user_id').count().withColumn('idcg', F.aggregate(F.sequence(F.lit(1), F.least(F.col('count').cast('int'), F.lit(k))), F.lit(0.0), lambda acc, i: acc + 1.0 / F.log2(i + 1)))
    per_user = users.join(ideal, 'user_id').join(observed, 'user_id', 'left').fillna({'hits': 0.0, 'dcg': 0.0})
    result = per_user.agg(F.avg(F.col('hits') / F.col('count')).alias('recall_at_10'), F.avg(F.col('dcg') / F.col('idcg')).alias('ndcg_at_10')).first().asDict()
    result.update(users=users.count(), catalog_coverage=recommendations.select('item_id').distinct().count() / catalog_size)
    return result

8. Холодный старт и гибрид¶

Неизвестный фактор пользователя или книги даёт NaN. coldStartStrategy="drop" только скрывает такие строки и не решает проблему. Одна явная train-оценка математически достаточна для фактора пользователя, но не гарантирует хорошую персонализацию. Один ноль не участвует в нашем явном ALS. Новая оценка после обучения сама по себе не обновляет сохранённую модель.

Гибрид: тёплый пользователь получает ALS; холодный без предпочтений — популярное; холодный с выбранными ISBN — совпадение автора (+2) и издателя (+1), затем популярность при равенстве. Остаток списка заполняется популярным. История и выбранные ISBN всегда исключаются. У контентного пути есть ограничения: издатель слишком широкий сигнал, а жанров в данных нет. Книги без ALS-фактора доступны контентному пути; отдельный пример показывает такие книги. Отсутствие фактора не доказывает, что книга недавно опубликована.
