# Задание 2. Рекомендательные системы в PySpark

Решение — [work/book_recommendations.ipynb](work/book_recommendations.ipynb). Вся логика находится в ноутбуке, вместе с результатами выполненного запуска. Исходный `pyspark_als_demo.ipynb` и его `demo_data` сохранены отдельно.

## Запуск

1. Запустить Docker Desktop с WSL 2.
2. Скачать [Book Recommendation Dataset](https://www.kaggle.com/datasets/arashnic/book-recommendation-dataset), распаковать `Ratings.csv`, `Books.csv`, `Users.csv` в `task2_pyspark_als/work/data/`.
3. В терминале из папки `task2_pyspark_als` выполнить:

```powershell
docker compose up -d
```

4. Открыть [Jupyter](http://127.0.0.1:8888/?token=pyspark_ml), затем `work/book_recommendations.ipynb`.
5. Выбрать **Kernel → Restart Kernel and Run All Cells**, дождаться расчёта и сохранить **Ctrl+S**. Уже сохранённые результаты можно читать без запуска.
6. Остановить контейнер из той же папки:

```powershell
docker compose down
```

Задания запускаются по очереди, поскольку используют один порт. Папка `work` подключена с компьютера и остаётся после остановки контейнера. CSV не хранятся в Git.

Compose содержит образ Spark 3.5.3, порт 8888, подключение `work` и настройки Python и памяти. Драйверу выделено 4 ГБ, численным библиотекам — до шести потоков. `local[6]` запускает Spark на шести потоках одного контейнера. Это локальная учебная среда; для многомашинного кластера потребовались бы отдельные узлы. Желательно иметь 16 ГБ RAM и выделить Docker хотя бы 6 ГБ.

## Что делает каждая ячейка

Номера совпадают с заголовками в ноутбуке.

| № | Содержание и объяснение |
| --- | --- |
| 1 | Создаётся Spark-сессия. `shuffle.partitions=12` ограничивает число разделов при join и группировках. |
| 2 | Читаются три CSV. ISBN сохраняется строкой, чтобы не потерять ведущие нули. Названия столбцов упрощаются. `multiLine` и `escape` позволяют читать названия книг с кавычками. Метаданные оставляются в одной строке на ISBN. |
| 3 | График показывает частоты оценок 0–10, таблица — активных пользователей. Проверяются повторные пары, отсутствие описаний книг и необычный возраст. Возраст не используется моделью. |
| 4 | Оценки 1–10 — явные предпочтения; 0 — взаимодействие без явной оценки. Для повторов пары берётся средняя положительная оценка. `row_number` назначает целочисленный `book_id`, необходимый ALS. Все пары делятся случайно на 80/10/10; в обучение и оценку explicit ALS идут только ненулевые оценки. Полная train-история остаётся для популярности и исключения прочитанного. |
| 5 | Популярность — число разных читателей в train, включая взаимодействия с оценкой 0. Топ-10 соединяется с названиями и авторами. Validation и test не влияют на популярность. |
| 6 | Выбирается самый активный пользователь по явным оценкам train. Join на `book_id` находит общие книги с другими читателями. Для каждой пары считаются число общих книг и средняя абсолютная разница оценок. Остаются три лучших соседа с минимум пятью общими книгами. |
| 7 | Соседи предлагают книги с оценкой не ниже 8. `left_anti` исключает все известные взаимодействия целевого пользователя в train, в том числе оценки 0. Книги упорядочиваются по числу голосов, затем по среднему баллу с весами сходства. |
| 8 | Базовая ALS с рангом 10, регуляризацией 0.1 и десятью итерациями. Функция оценки вычисляет RMSE только для конечных предсказаний и отдельно показывает coverage — долю тестируемых пар, для которых модель смогла дать оценку. |
| 9 | Новый эксперимент: регуляризация увеличена до 0.3. Базовая модель не заменяется; результаты выводятся рядом. |
| 10 | Ещё один эксперимент: ранг увеличен до 20 при регуляризации 0.3. Сравниваются все три варианта на validation. |
| 11 | По минимальному validation RMSE выбирается победитель. Test используется для итоговой оценки. Для проверки полезности ALS рядом вычисляется RMSE простого среднего train на тех же известных тестовых парах. Предсказания соединяются с названиями книг. |
| 12 | Три примера: новый пользователь, книга без обученного фактора и пользователь с одной явной оценкой train. `coldStartStrategy="nan"` сохраняет неизвестные пары и показывает NaN вместо скрытого удаления. |
| 13 | `recommend_books` проверяет наличие фактора пользователя. Для известного пользователя ALS оценивает непрочитанные книги с доступным описанием; для неизвестного используется популярность. Возвращаются три книги с названиями, авторами, баллом и источником рекомендации. Показаны активный, новый и малоактивный пользователи. |
| 14 | Пример улучшения холодного старта: новый пользователь выбирает понравившуюся книгу (в примере ISBN `0316666343`, «The Lovely Bones»), затем рекомендации строятся по автору и издателю. Совпадение автора даёт 2 балла, издателя — 1. Отдельно показаны подходящие книги без ALS-фактора: контентный подход способен рекомендовать и их. |
| 15 | Завершается Spark-сессия. Контейнер после сохранения останавливается командой `docker compose down`. |

### Основные параметры

- `rank` — размер скрытых векторов пользователя и книги. Больший ранг позволяет описывать более сложные предпочтения, но требует больше данных и вычислений.
- `regParam` — сила штрафа за сложность факторов; помогает уменьшать переобучение.
- `maxIter=10` — число чередующихся обновлений факторов.
- `seed=42` — фиксированное начальное состояние случайного генератора.
- `implicitPrefs=False` используется по умолчанию: модель прогнозирует явные оценки, нули не подаются как «плохая оценка».

Сходство соседей: `n / (n + 10) × (1 − MAE / 9)`, где `n` — число общих книг, MAE — среднее абсолютное расхождение оценок. Деление на 9 соответствует максимальной разнице между 1 и 10. Множитель `n / (n + 10)` снижает доверие к совпадениям по небольшому числу книг. Это выбранная учебная эвристика, а не обученная метрика.

## Результаты

Запуск 13 октября 2026 года. В данных 1 149 780 взаимодействий: 433 671 явная оценка и 716 109 нулей. Пользователей — 278 858. В исходном Books.csv 271 360 строк; после приведения ISBN к верхнему регистру, удаления пробелов по краям и повторов осталось 271 046 записей. Для 118 641 взаимодействия нет описания книги: такие оценки сохраняются, а название при соединении остаётся пустым.

Явные оценки разделились на 346 931 / 43 201 / 43 539 строк train/validation/test. Самая популярная книга в train — **Wild Animus**, 1 988 разных читателей. Для активного пользователя **11676** выбраны соседи **98391, 95359, 16795**: у них соответственно 171, 93 и 112 общих оценённых книг с целевым пользователем.

| ALS | Validation RMSE | Coverage |
| --- | ---: | ---: |
| rank=10, regParam=0.1 | 3.7536 | 58.98% |
| rank=10, regParam=0.3 | 2.9966 | 58.98% |
| rank=20, regParam=0.3 | 2.9324 | 58.98% |

Выбрана модель с **rank=20, regParam=0.3**. На test её **RMSE = 2.9593, coverage = 59.21%**. Прогноз среднего train на тех же известных парах даёт **RMSE = 1.8064**. Подбор улучшил ALS относительно первого эксперимента, но **ALS не превзошла простой средний прогноз**. Нельзя по этим результатам утверждать, что получены качественные персональные рекомендации. Разреженность данных и отсутствие отдельных пользовательских и книжных смещений у этой простой модели могут быть причинами; это гипотезы, а не проверенный вывод о причинах ошибок.

Для нового пользователя и книги без фактора получен NaN. Пользователь **9** с одной явной оценкой train получил конечный прогноз, но его значение около 0.495 для выбранной книги демонстрирует, что техническая возможность предсказать ещё не означает хорошее качество.

Гибрид выдал топ-3 для активного, нового и малоактивного пользователей. Новому предложены **Wild Animus**, **The Lovely Bones**, **The Da Vinci Code**. В контентном примере показаны книги Alice Sebold, включая книги без ALS-фактора.

Единица рекомендации здесь — ISBN. Разные издания одной книги имеют разные ISBN и считаются отдельными объектами; поэтому в контентной выдаче могут встречаться другие издания уже выбранного произведения. Объединение изданий в произведения в этом задании не выполняется.

## Как объяснить преподавателю

**Почему популярность — слабая персонализация?** Все новые пользователи видят один список. Он игнорирует интересы, продвигает уже известные книги и почти не даёт шанса редким новинкам. Зато прост, быстро считается и не требует истории нового пользователя.

**Почему ручной поиск соседей плохо масштабируется?** Для одного выбранного пользователя достаточно join по общим книгам. Для всех пользователей число сравниваемых пар может расти квадратично; данные разрежены, общих оценок часто мало. В Spark ML нет готовой модели классического user-user поиска соседей: ALS даёт компактное распределённое представление. Это не означает, что поиск соседей нельзя реализовать на Spark — он сделан в ячейках 6–7.

**Что делает ALS?** Приближает матрицу оценок произведением двух небольших матриц: факторов пользователей и факторов книг. Скалярное произведение соответствующих векторов — прогноз оценки. Метод по очереди фиксирует одну матрицу и обновляет другую. Результат может выходить за шкалу 1–10; здесь прогнозы не обрезаются и используются как баллы ранжирования.

**Что происходит с новым пользователем?** Без фактора пользователя ALS возвращает NaN. То же происходит с неизвестной книгой. `coldStartStrategy="drop"` мог бы удалить такие строки, но тогда необходимо отдельно сообщать coverage; здесь неизвестные пары сначала сохраняются явно.

**Достаточна одна оценка?** Одна явная оценка в обучении позволяет построить фактор пользователя и получить прогноз для известной модели книги. Это не гарантирует качественной персонализации. Нулевая оценка не попадает в нашу explicit ALS. Оценка, поставленная уже после обучения, также не обновляет существующую модель автоматически.

**Что показывает RMSE?** Корень среднего квадрата ошибки числовых оценок, в единицах шкалы 1–10. Он сильнее штрафует большие ошибки. Это не непосредственная оценка качества топ-3: хорошая точность оценки не обязательно означает правильный порядок рекомендаций. Для полноценной оценки ранжирования понадобились бы Recall@K/NDCG@K и проверка реального пользовательского отклика; в задании рассчитывается RMSE.

**Почему нужна coverage?** RMSE считается только на парах с известными факторами. Без доли таких пар низкая ошибка может скрывать неспособность обслуживать значительную часть пользователей или книг. Популярность помогает обслужить холодных пользователей, но её качество не описывается RMSE ALS.

**Как сделать холодный старт умнее?** Попросить выбрать несколько любимых книг или жанров. Уже одного выбора достаточно для простой рекомендации по метаданным, как в ячейке 14. Место проживания можно использовать для региональной популярности, если данных достаточно. В датасете нет полноценной разметки жанров, поэтому пример использует доступные автора и издателя. Совпадение издателя — слабый сигнал: такие рекомендации демонстрируют механизм, но не гарантируют похожее содержание.

**Что делать с холодными книгами?** Использовать автора, издателя, описание и другие метаданные; добавлять такие книги в рекомендации как контентные кандидаты. ALS сам не создаст фактор книги без обучающих взаимодействий. В примере специально показаны книги без такого фактора.

**Почему разбиение случайное?** В Ratings.csv нет времени взаимодействий. Делятся уникальные пары пользователь–книга, чтобы одна пара не оказалась одновременно в обучении и тесте. Неизвестные пользователи и книги в test допустимы и отражены в coverage. Понятие «не читал» в рекомендациях означает отсутствие книги в доступной train-истории, а не отсутствие во всём датасете: отложенные взаимодействия не подглядываются.

**Почему метаданные из всего каталога не считаются утечкой оценок?** Словарь ISBN и описания используются как доступный каталог, а не как предпочтения пользователей. ALS и популярность обучаются только на train.

Чтобы получить рекомендации для другого пользователя, после обучения и до `spark.stop()` добавить ячейку `display(recommend_books(11676).toPandas())`, заменив число на нужный ID. Отдельного сервиса или модуля для этого не требуется.
