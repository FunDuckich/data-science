# Задание 1. Поиск мошеннических транзакций

Решение — [work/fraud_detection.ipynb](work/fraud_detection.ipynb). В ноутбуке находятся код, таблицы и графики выполненного запуска. Демонстрационный `pyspark_ml_demo.ipynb` сохранён отдельно.

## Запуск

1. Установить и запустить Docker Desktop с WSL 2.
2. Скачать [Credit Card Fraud Detection](https://www.kaggle.com/datasets/mlg-ulb/creditcardfraud) и положить `creditcard.csv` в `task1_pyspark_ml/work/data/`.
3. Открыть терминал в папке `task1_pyspark_ml` и выполнить:

```powershell
docker compose up -d
```

4. Открыть [Jupyter](http://127.0.0.1:8888/?token=pyspark_ml), затем `work/fraud_detection.ipynb`.
5. Для повторного расчёта выбрать **Kernel → Restart Kernel and Run All Cells**. Результаты уже видны без запуска. При первом старте Docker скачает образ; обучение занимает несколько минут.
6. Сохранить ноутбук через **Ctrl+S** и остановить контейнер из той же папки:

```powershell
docker compose down
```

Запускать задания по очереди: оба используют порт 8888. Файлы в `work` остаются после остановки. Датасет и сохранённая модель не добавляются в Git.

Compose упрощён: оставлены образ Spark 3.5.3, порт, папка `work` и настройки среды. `PYSPARK_SUBMIT_ARGS` выделяет драйверу 4 ГБ, `PYTHONPATH` подключает библиотеки Spark, переменные потоков ограничивают численные библиотеки шестью потоками. В ноутбуке `local[6]` означает локальный Spark с шестью рабочими потоками в одном контейнере; это учебная среда, не кластер из нескольких машин. Желательно иметь 16 ГБ оперативной памяти и выделить Docker хотя бы 6 ГБ.

## Что делает каждая ячейка

Номера соответствуют заголовкам ноутбука.

| № | Содержание и объяснение |
| --- | --- |
| 1 | Импорты и `SparkSession`: точка входа для DataFrame и Spark ML. `shuffle.partitions=12` задаёт число разделов при перераспределении данных. |
| 2 | `read.csv` читает файл, `inferSchema` определяет числовые типы. `cache` сохраняет часто используемый DataFrame. `show` и `printSchema` показывают примеры и схему. Проверяются пропуски и полные повторы; `dropDuplicates` удаляет их. `Class` переименован в стандартный для ML столбец `label`. |
| 3 | Три графика: дисбаланс классов, распределение суммы и распределение времени. Логарифм суммы помогает увидеть небольшие операции на фоне крупных. Нормировка гистограмм позволяет сравнивать формы распределений классов разного размера. |
| 4 | Квантили времени дают последовательные train/validation/test примерно 60/20/20. Операции с одинаковым временем не попадают по разные стороны границы. `V1…V28` и `Amount` — признаки; `Time` используется для разделения. `VectorAssembler` собирает вектор, `StandardScaler` центрирует и масштабирует признаки. |
| 5 | Общая небольшая функция оценки: `numBins=0` сохраняет все пороги PR-кривой; считает PR-AUC, precision, recall, F1 и четыре числа матрицы ошибок. Кэш предсказаний освобождается после оценки. |
| 6 | Базовый `Pipeline`: сборка признаков → масштабирование → логистическая регрессия. `fit(train)` обучает все стадии, `transform(valid)` получает предсказания. Масштабирование обучается только на train. |
| 7 | Следующий эксперимент: мошенничеству назначен вес 10, обычной операции — 1. Это увеличивает вклад редкого класса в функцию потерь. Исходная модель и её результат сохранены отдельно. |
| 8 | Случайный лес: 50 деревьев глубины до 5. Деревьям не нужно масштабирование, поэтому pipeline состоит из сборки вектора и классификатора. |
| 9 | `ParamGridBuilder` создаёт четыре сочетания числа деревьев 50/100 и глубины 5/10. `TrainValidationSplit` делит только train в отношении 80/20 и выбирает параметры по PR-AUC. Лучший pipeline автоматически переобучается на всём train. Затем он оценивается на внешней validation вместе с предыдущими моделями. |
| 10 | Победитель выбирается по PR-AUC на validation, после чего оценивается на test. Матрица ошибок показывает реальные количества пропусков и ложных тревог. Порог классификации остаётся стандартным 0.5. |
| 11 | Для сравнения библиотек берётся около 35% каждого класса train с `seed=42`. На этой общей выборке обучается отдельная логистическая регрессия Spark без регуляризации. Измеряется только время `fit`. |
| 12 | sklearn получает те же строки и признаки, использует масштабирование и логистическую регрессию без регуляризации. Тестовая выборка тоже общая. Для прямого сравнения обеих библиотек AP считается одной функцией sklearn; это устраняет отличие способов интегрирования PR-кривой. |
| 13 | `write().overwrite().save()` сохраняет весь обученный pipeline в `work/models/fraud_pipeline`. `PipelineModel.load()` загружает его. На 100 тестовых строках сравниваются признаки, предсказания и вероятности через `exceptAll` в обе стороны. Ноль различий означает совпадение проверенных результатов. |
| 14 | `spark.stop()` завершает Spark-сессию. Сам контейнер останавливается командой из инструкции запуска. |

`maxIter` ограничивает число итераций логистической регрессии, `regParam` задаёт силу регуляризации. `standardization=False` отключает повторное внутреннее масштабирование, поскольку перед моделью уже стоит `StandardScaler`. `seed=42` фиксирует случайность выборки и леса; это не обещание одинакового времени выполнения на разных компьютерах.

## Результаты

Запуск 13 октября 2026 года. После удаления 1 081 полного повтора осталось 283 726 транзакций, в том числе 473 мошеннических. Train: 170 037 строк / 342 мошенничества; validation: 56 738 / 57; test: 56 951 / 74.

| Эксперимент | Validation PR-AUC | Precision | Recall | F1 |
| --- | ---: | ---: | ---: | ---: |
| Логистическая регрессия | 0.7737 | 1.0000 | 0.0175 | 0.0345 |
| Регрессия с весом 10 | 0.7525 | 0.7213 | 0.7719 | 0.7458 |
| Лес, 50 деревьев, глубина 5 | 0.7475 | 0.9487 | 0.6491 | 0.7708 |
| Подобранный лес, 50 деревьев, глубина 10 | 0.7564 | 0.9286 | 0.6842 | 0.7879 |

По заранее выбранной метрике PR-AUC победила базовая регрессия. На test: **PR-AUC 0.7947, precision 1.0000, recall 0.2027, F1 0.3371**. Она нашла 15 мошенничеств из 74, пропустила 59 и не дала ложных тревог. Это показывает различие между качеством ранжирования и качеством решений при конкретном пороге: лучшая PR-AUC не означает лучшую полноту при пороге 0.5. Для практического поиска мошенничества такой recall недостаточен; следующим экспериментом был бы выбор порога на validation с учётом стоимости ошибок. В этом учебном сравнении порог фиксирован, а ограничения результата показаны явно.

Вес редкого класса заметно повысил recall при том же пороге, но не PR-AUC. Более глубокий лес немного улучшил PR-AUC и F1 относительно базового леса, однако не превзошёл регрессию по критерию выбора.

Сравнение библиотек на одних 59 454 обучающих строках и общем test:

| Библиотека | Average precision | Precision | Recall | F1 | Время fit, с |
| --- | ---: | ---: | ---: | ---: | ---: |
| Spark | 0.6391 | 0.7170 | 0.5135 | 0.5984 | 6.16 |
| sklearn | 0.6389 | 0.7170 | 0.5135 | 0.5984 | 0.69 |

Это отдельные модели без регуляризации на меньшей выборке, поэтому их не следует путать с выбранной итоговой моделью. Время относится к одному локальному запуску и не включает чтение CSV и перенос данных в pandas. При загрузке сохранённого pipeline на 100 тестовых строках получено **0 различий**.

## Как объяснить преподавателю

**Что решаем?** Бинарную классификацию: `label=1` — мошенничество, `label=0` — обычная транзакция. `V1…V28` — обезличенные признаки после PCA, их исходный экономический смысл неизвестен.

**Почему не accuracy?** Мошенничеств очень мало. Если всегда отвечать «обычная операция», accuracy будет высокой, но ни одно мошенничество не найдётся. PR-AUC описывает соотношение точности и полноты положительного класса при разных порогах. Precision — доля настоящих мошенничеств среди тревог; recall — доля найденных мошенничеств; F1 — их гармоническое среднее. Для банка выбор рабочего порога зависит ещё и от стоимости пропуска и ложной блокировки; здесь эти стоимости неизвестны.

**Почему делим по времени?** Модель проверяется на более поздних транзакциях. Полные дубликаты убраны до разделения. Validation нужна для выбора модели; test не участвует в обучении и подборе параметров. Внутреннее случайное разделение TrainValidationSplit — упрощение учебного подбора, а внешние validation и test сохраняют временной порядок.

**Pipeline и PipelineModel — в чём разница?** Pipeline описывает шаги. После `fit` получается PipelineModel с уже вычисленными параметрами масштабирования и обученным классификатором. Сохраняется вся цепочка, поэтому при загрузке не требуется заново обучать scaler.

**Зачем несколько экспериментов?** Базовая регрессия показывает отправную точку. Веса меняют внимание к редкому классу, лес проверяет нелинейные зависимости, подбор параметров проверяет пользу усложнения леса. Улучшение не гарантировано; выбирается фактический результат validation.

**Чем Spark отличается от sklearn?** Spark выполняет операции над разделами DataFrame и может работать на нескольких машинах. sklearn работает с массивами в памяти одного процесса. На небольшом наборе накладные расходы Spark могут сделать его медленнее. Здесь обе библиотеки запущены на одной машине, поэтому замер не доказывает превосходства на большом кластере. `toPandas` собирает данные в память драйвера и уместен только для небольшого сравнения и графиков.

**Почему AP из sklearn и PR-AUC из Spark могут различаться?** Это разные способы суммирования площади под PR-кривой. В сравнении библиотек используется один и тот же `average_precision_score` для обеих моделей. Различия оптимизаторов и нормировки стандартного отклонения также могут немного влиять на результат.
